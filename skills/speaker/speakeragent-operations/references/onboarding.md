# Onboarding without a platform dependency

Read existing onboarding.json and supplied speaker materials first. In the first interactive reply, if the choice was not answered and has not yet been asked, explicitly ask: “Do you want to create a SpeakerAgent.ai account, connect an existing account, or work independently without one?” Do not merely announce that an account is optional or silently choose undecided. Keep other intake questions compact, preferably start with their speaker sheet/site and key booking constraints. Explain the dashboard can be convenient, while the agent can research, qualify, personalize and maintain the pipeline locally. Do not ask again after a refusal or imply that refusal lowers the evidence standard.

Save `platform_choice` as `requested`, `existing`, `declined` or `undecided`, plus the time of the answer. `account_connected` stays false until access is tested. If declined, use local cases and browser/public research immediately. If requested, help through the real official signup and let the person handle passwords, verification, payment and terms as appropriate; continue independent research while signup is unfinished. Do not create an account merely because the client asked whether one is available. If existing, test the scoped connection or dashboard without publishing or modifying their profile unexpectedly.

For a new speaker, collect name and credible background, talk topics, audience, geography/remote preferences, date horizon, paid-only or exposure goals, minimum fee/currency if applicable, exclusions and travel constraints. Read their supplied site/LinkedIn/speaker sheet before asking. Confirm what matters in a short conversational brief. A coach uses separate client identities, voices, criteria and workspaces. If enough was already supplied, start work without repeating intake.

For proactive daily operation, record the requested daily research time and timezone, useful batch target, what counts as a new opportunity, model/tool cost authority, and where the brief should appear. Offer a reasonable research target such as up to five reviewed opportunities per day, with an honest shortfall when fewer qualify. A recurring target is not a promise of five paid invitations every day. Configure delivery only to the client's chosen destination; local reports work without messaging accounts.

Populate actual persona.json and mission.json; do not copy the fictional example persona as a real client. Prepare the workspace with runtime/prepare.py. `--daily-authorized` records an actual request for daily work; it does not create or enable the schedule. Run a bounded first cycle, review source evidence and saved artifacts, then finish the authorized daily setup. Do not ask for a second permission to do the same daily research once the client has already requested it and supplied limits.

The independent prerequisites are an operational Hermes model, usable public search or browser, writable persistent storage, and a running supervisor/scheduler for daily work. These are runtime capabilities, not a requirement for SpeakerAgent.ai, One API, LinkedIn Premium, or a paid enrichment vendor. If search is unavailable, use browser search and known official calendars; if both fail, report the actual research-access dependency while preserving the mission.
