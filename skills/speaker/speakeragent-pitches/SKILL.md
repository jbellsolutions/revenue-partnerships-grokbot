# Personalized pitch preparation

Read the persona, selected topic and current opportunity case. Do not write around missing credentials, a false contact identity, an expired call or incompatible session eligibility. State the missing requirement and continue research when possible.

Preserve the three layers: one checked detail about the show/event/person; one supported connection from the speaker's experience or topic; one concrete audience-value bridge. With a strong evidenced personal connection, state only the shared fact. With medium confidence, describe resonance rather than identical lived experience. With weak/no connection, use the professional topic fit.

A refined podcast hook uses exactly one selected episode detail. Priority in the original selector is notable moment, specific topic, theme, then title. Preserve whether it came from a transcript, show notes or title; do not imply a transcript was reviewed when only metadata was available.

Use the client's writing samples only for style. The original HC hook is 60–90 words and CTA 15–25; the full email writer targets 150–220 words. Adapt to the client's preference and application limits. Use first person, business-casual language, a specific opening, a natural bridge and a soft final ask. Avoid corporate filler, unsupported praise, invented listening history and invented shared experiences. No automatic “I've been following/listening” opener.

Run three passes in one agent unless the environment explicitly authorizes multiple workers:

1. Writer: grounded first draft addressed to the actual person or team.
2. Authenticity checker: compare every factual claim to the evidence; verify style, specificity and naturalness. Revise at most twice in the source pattern. If still unsupported, withhold the draft as not ready.
3. Editor: improve subject, clarity, audience value and ask without introducing facts.

For applications, answer the actual prompts, obey word limits, use approved talk title/abstract, disclose vendor status accurately and save the completed draft without submitting. For email, save subject/body separately from the evidence notes so citations are not awkwardly inserted into the recipient-facing copy.

Keep recipient, source evidence, draft version, review outcome and submission route in the case. Sending, scheduling, form submission and marking `Contacted` require the user's actual instruction and a confirmed action result. The bundled SpeakerAgent CLI itself does not send email.
