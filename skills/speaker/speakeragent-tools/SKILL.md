# Tool selection and account operation

Start with available capabilities, not a required vendor stack. For independent work, a search tool, public-page reader/browser and writable case storage are enough. Verify each can retrieve one relevant source and save/read a case. Use official RSS or public APIs where they reduce work; use a browser for rendered pages and forms.

Read [CLI and dashboard](references/cli-dashboard.md) when using SpeakerAgent. Read [One API](references/one-api.md) only when the destination has that connection. If neither exists, keep researching with native tools. Do not create accounts or mint keys merely to conduct a read-only review.

When a capability is missing, state the practical limitation: search unavailable, rendered page blocked, provider not configured, scoped account unavailable, or no durable storage. Continue independent work. Do not invent command names, browser functions, endpoint paths, credentials or provider access.

Separate tool receipts from verified research. Inspect the actual page/result and preserve source URLs. Track provider spend and uncertain calls. A list of available tools or successful health check does not establish an end-to-end research workflow.

Preserve the host's command approval policy. In unattended Hermes sessions an inline shell/Python command can be refused even when file tools are available. Use supported read_file/write_file/browser tools or another allowed method; do not enable approval bypasses to keep the job moving. Report a real capability blocker and save partial work when no permitted method remains.
